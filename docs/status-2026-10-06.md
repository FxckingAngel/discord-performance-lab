## New Phase 2 attribution evidence

The authenticated CDP performance window measured almost no JavaScript, layout, or style-recalculation time during idle. CDP process IDs also correlate directly with Windows PIDs for the browser, renderer, GPU, network, and storage roles. The current evidence therefore points to native Chromium/GPU/runtime allocations and process overhead rather than a measured page-level scripting loop. No normal-shell Chromium flags or forced collection behavior has been added.

## Current conclusion

EcoQoS remains a private, background-idle experiment. Stock Discord remains the Track A reference for active use. Track B now has a verified-build comparison showing a large reduction in resident-private memory and CPU, while private bytes remain slightly above the 250 MiB design target and one extra WebView2 service remains in the tree. The repository must stay private until a shell passes the same-workload comparison and the required functional checks.
