# Stock baseline: Discord PTB

## Run identity

- Build: Discord PTB `1.0.1223`
- Electron: `42.11.10`
- Scenario: idle observation
- Observation: 6 samples at 5-second intervals
- Collection: read-only process-tree sampling by PID and parent PID
- Raw data: local file under `benchmarks/raw/`, not committed

## Observed result

| Metric | Observed value |
| --- | ---: |
| Process count | 6 throughout the sampled run |
| Working set median | 732.9 MiB |
| Private memory median | 1,334.2 MiB |
| CPU time delta | 4.734 seconds over the 25-second observation window |

The working-set figure is resident memory at the sample time. Private memory is reported separately because neither number alone describes the complete system cost of the client.

## Repeatability check

Three additional 15-second idle runs used the same live client and collector:

| Run | Processes | Working set median | Private memory median | CPU-time delta |
| --- | ---: | ---: | ---: | ---: |
| 1 | 6 | 809.6 MiB | 1,414.1 MiB | 3.641 s |
| 2 | 6 | 712.9 MiB | 1,309.1 MiB | 4.141 s |
| 3 | 6 | 736.1 MiB | 1,334.4 MiB | 2.703 s |

The memory spread is large enough that a candidate must be tested with repeated runs and reported with distributions. A single favorable sample is not evidence of an optimization.

## Profile facts

The active PTB profile contained an empty `chromiumSwitches` object. The scan found no obvious user-facing hardware-acceleration setting in the small profile settings files inspected. The profile also contained Discord-selected settings for audio initialization and media startup; these were not changed.

## Limitations

This is a stock baseline, not an optimization result. It does not establish startup time, active workload cost, responsiveness, voice quality, screen sharing, notification behavior, or repeatability across multiple runs. Those measurements remain required before accepting a candidate.
